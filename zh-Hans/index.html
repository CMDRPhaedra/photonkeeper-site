Photonkeeper

把 DWARF 3 或 DWARF Mini 上的拍摄记录，搬进你自己硬盘上一份像样的存档 — 再写回去时逐字节完全相同，望远镜照样能对它做叠加和重新叠加。

macOS 14 或更高版本 · Windows 10 (1809) 或更高版本
支持 DWARF 3 与 DWARF Mini。两者都用真实数据验证过：DWARF 3 由我本人测试，Mini 由一位机主完整跑过一遍来回流程。DWARF II 的存档也能读取 — 用“存档”→“从现有文件夹导入…”归入即可。我手上从未有过 DWARF II 实机，所以直接从它导入、或把拍摄记录发送回它，都属于未经测试，而不是确定不行。如果你的设备表现不对，或者哪里让你困惑，请告诉我：support@chryse.co.uk，欢迎附上截图。

它做什么

  • 把望远镜上所有新数据导入进来，并在复制的同时计算每个文件的 SHA-256 校验和，而不是复制完再单独跑一遍。
  • 既可以走数据线，也可以走你自己的 Wi-Fi 网络（“望远镜”→“通过 Wi-Fi 连接…”）。Wi-Fi 下可以导入和校验；发送回望远镜和释放机身空间需要 USB。
  • 把拍摄记录发送回望远镜 — 可按目标、日期、曝光或增益筛选 — 传出时计算哈希，写完后再读回确认。
  • 释放机身存储空间，但只针对那些刚刚与你的存档核对并校验通过的拍摄记录。
  • 把 M 42、M42 和 NGC 1976 归为同一个目标，而不是三个文件夹。
  • 日后可重新检查整个存档是否出现位腐，记住检查结果，并能从望远镜上重新取回损坏的文件。
  • 也回答问题的另一半 — 不只是文件自导入以来有没有变过，而是它现在还能不能作为一帧正常打开。
  • 可以导入整张卡，也可以只导入你从列表里挑出的那几条拍摄记录。
  • 你要求时才从存档中删除拍摄记录 — 而且是移入废纸篓（Windows 上是回收站），绝不直接抹掉；在没有废纸篓的网络驱动器上，则移入存档内的暂存文件夹。
  • 每一项操作都可以先试运行，准确显示接下来会发生什么。

拍摄记录文件夹永远不会被改名，里面的内容也不会被改动 — 所有整理都发生在它们上层的目录里。

没有望远镜也能试

Mac 版内置演示模式，带有示例数据和一份独立的示例存档，你可以先完整看一遍来回流程，再决定是否让它接触自己的拍摄数据。菜单：望远镜 → 试用演示模式。Windows 版暂时还没有。

系统要求

  • macOS 14 (Sonoma) 或更高版本（Apple 芯片或 Intel 均可），或 Windows 10 版本 1809 或更高版本（x64 或 ARM64）。
  • 一台 DWARF 3 或 DWARF Mini。全部功能需要通过 USB 连接；若只是导入和校验，走 Wi-Fi 也可以。
  • 一个存放存档的位置 — 外置硬盘也可以，而且即使你移动或重命名该文件夹，应用也会记住它。

两边是同一个应用，存档格式也相同：一边写出的硬盘，另一边可以照常读取，连校验和一起。需要注意的是，Windows 版目前只有英文界面，也还没有演示模式。

隐私

Photonkeeper 不收集任何关于你的信息。没有分析统计，没有遥测，没有崩溃报告，不需要注册账户，不需要校验许可证，也没有任何形式的追踪，应用里根本不含任何第三方代码。包括我在内，没有人会知道你拍了什么、什么时候拍的。

你的存档、它的清单与校验和，以及少量设置项，全都留在你自己的机器上。App Store 版本与 Microsoft Store 版本都只发起一种网络连接 — 连到你自己网络上、你自己的望远镜。版本检查在 Mac App Store 版本中于编译阶段就被完全移除，而 Windows 版本从来就没有写过这段代码，因为更新由商店负责。在 Photonkeeper 迁往 App Store 之前从本页下载的版本多了这一项检查，每天一次，并且可以关闭。

阅读完整隐私政策，其中逐条说明应用发起的每一个连接、你的数据究竟存放在哪里，以及你给我发邮件后会发生什么。

联系方式

缺陷、困惑或功能建议请发到 support@chryse.co.uk。如果出了问题，应用内“活动”面板的“日志”会留下记录，每次运行也会在存档中写一份。用“日志”里的“存储…”导出的文件，或者 _journal/logs/ 里最新的那一个，是你能提供的最有用的东西。
